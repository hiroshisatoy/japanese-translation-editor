# 翻訳ビューア

PO / POT の原文・取り込んだ訳文・変更後の訳文を比較して編集するローカルツールです。ファイルはブラウザー内で処理します。

公開サイト: https://hiroshisatoy.github.io/japanese-translation-editor/

## 下書きの自動保存

開いているファイルと編集中の訳文を、このブラウザーの IndexedDB に自動保存します。同じブラウザーでページを開き直すと、前回のファイルと下書きを復元します。保存状態と保存したファイル・下書きの件数は、右上の「設定」で確認できます。

同じ PO ファイルを再び開いたときも、保存した下書きを復元します。ファイル名と内容の両方が一致する場合にだけ適用するため、同名の別バージョンには下書きを引き継ぎません。複数ファイルや複数形の訳文にも対応しています。PO を書き出したあとも下書きは残ります。

書き出すファイル名は `YYYYMMDDhhmmss_元のファイル名_フィルター名.po` です（例：`20261112120405_sample_All.po`）。日時はブラウザーのローカル時刻です。通常はフィルター名に現在選択している状態を付け、読み込まれた翻訳文字列をすべて書き出します（廃止項目を除く）。

設定の「書き出し」で「変更した項目だけを書き出す」を有効にすると、読み込んだ訳文と異なる項目だけを書き出します。元に戻した項目や、変更がないファイルは含めません。PO のヘッダー、文脈、コメント、複数形の全訳文は保持します。この場合、ファイル名の末尾は `_changed.po` になります。どちらの設定も検索や画面の絞り込みには左右されません。書き出しても下書きは残ります。この設定はブラウザーに保存され、次回も引き継ぎます。

設定から、現在開いているファイル、ほかの保存済みファイル、下書きだけ、設定情報だけ、または一時保存のすべてを選んで削除できます。現在のファイルや下書きを削除すると、画面の編集内容も取り込んだ訳文に戻ります。現在のファイルを削除した場合は、次に編集すると自動保存を再開します。設定情報を削除すると、すべての項目を書き出す初期設定に戻ります。

右上の「ファイルを閉じる」で選択画面に戻れます。「PO ファイルを開く」「見本を表示」の下に保存済みファイルの一覧があり、「開く」から元のファイルを選び直さずに下書きを復元できます。一覧にはファイル名、プロジェクト情報、下書き件数、文字列数、同名の別バージョンを区別する保存 ID を表示します。長いファイル名とプロジェクト情報は横スクロールで確認できます。保存できなかった場合は、変更を破棄する前に確認画面が表示されます。

ファイルと訳文は外部に送信しません。保存先は端末・ブラウザー・サイトごとに異なります。ブラウザーのサイトデータを削除した場合や、プライベートブラウズを終了した場合などは復元できないため、残したい訳文は PO に書き出してください。保存容量の不足などで保存に失敗したときも、編集と書き出しは継続できます。

## GitHub Pages

`main` へのプッシュで GitHub Actions が `npm ci` と `npm run build:pages` を実行し、`_site/` を GitHub Pages に公開します。リポジトリの **Settings → Pages → Source** は **GitHub Actions** を選択します。

`_site/` には画面、ビルド済みコンポーネント、見本の PO ファイルを配置します。相対パスを使用しているため、GitHub Pages のプロジェクト配下でも動作します。利用者が開いた PO ファイルや編集中の訳文をサーバーへ送信する処理はありません。

## 起動

`index.html` をブラウザーで開くか、`npm start` でローカルサーバーを起動します。前回の作業がない場合は、PO ファイルを開くか「見本を表示」を選択します。見本は `test/sample.po` を読み込み、直接開いた場合は内蔵の見本を使います。前回の作業が保存されている場合は自動的に復元します。

## UI の変更

`npm ci` のあと `npm run build` を実行します。`ui.jsx` は WordPress 公式の `@wordpress/components` 44.0.0 と、実験段階の `@wordpress/ui` 0.26.0、デザイントークンの `@wordpress/theme` 4.0.0 を使用しています。ビルド済みの `dist/wp-ui.js` と `dist/wp-ui.css` を配布物に含めてください。実行時に CDN 接続は不要です。

検索・状態選択・ボタン・ヘルプダイアログを React が管理し、PO の解析、編集、書き出し、仮想一覧は既存の `app.js` と `po-parser.js` が処理します。

## 動作確認

`npm start` で起動して `npm test` を実行します。初回は `npx playwright install chromium` が必要です。ブラウザーの実行ファイルを指定する場合は `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` を設定してください。
